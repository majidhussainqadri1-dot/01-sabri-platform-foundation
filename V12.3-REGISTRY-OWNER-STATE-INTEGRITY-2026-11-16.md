# File 01 V12.3 — persisted module owner/state integrity correction

**Date:** 16 November 2026. **Requirement:** F01-FR-002/F01-FR-003, module registry and fail-closed dependency readiness. **Scope:** repository-source candidate only. This is not a claim of an observed Live failure.

## Root cause, proven red

The original `SPF_Registry::module_dto()` accepted `manifest_json` as structurally valid when `module_key`, software/contract versions and required/optional dependencies matched, but **did not compare the manifest's owner_file, owner_name, slug, namespace_prefix and state to the authoritative persisted row**. A tampered or stale stored manifest could contradict its own canonical owner/state and still lead `SPF_Dependency_Resolver::readiness()` to return `ready=true`.

An isolated disposable WordPress/MySQL fixture first corrupts `owner_file`, then `state`, each without changing its canonical module row, and expects `module_manifest_invalid`. It restores exact prior module JSON and software version in `finally`. **Test-only commit:** `1cf99ce18f8cbb7a9d0a3c3edb1bb37c3d6b3796`. **GitHub Actions Run 43798588710** failed solely the WordPress/MySQL job with the two intended messages: `manifest owner_file drift was wrongly treated as ready`, `manifest/row state drift was wrongly treated as ready`. PHP 8.1 and 8.3 source jobs both passed. The issue is proven against that exact repository candidate, not deployed Hostinger.

## Bounded correction

Add strict equality checks for `owner_file`, `owner_name`, `slug`, `namespace_prefix`, `state` in `SPF_Registry::module_dto()` alongside existing module_key/software/contract checks. Every legitimate `SPF_Registry::register_manifest()` write persists those row columns from the same normalized manifest in one transaction; no other File01 source writes the modules registry in this scope. Thus rejecting mismatched persisted identity remains consistent with normal owner transitions and preserves its fail-closed semantics.

**No new columns, table migrations, roles, authority, routes or companion writes.** The test is a synthetic, cleaned-up CI fixture, not live data. Current exact-head CI/package and independent acceptance are mandatory before merge or deployment.
