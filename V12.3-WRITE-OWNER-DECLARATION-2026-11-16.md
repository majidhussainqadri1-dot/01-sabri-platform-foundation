# F01-FUT-003 — incomplete canonical write declaration must fail closed

**16 Nov 2026**, File 01-B V12.3 Draft PR #14 source-only. No evidence this defect occurs on currently deployed Hostinger.

## Red proof of root cause

`SPF_Governance_Control_Plane::lint_architecture()` previously treated a malformed `writes` item as `target=''` and silently skipped validation. When a module claimed a valid entity/route but its own write object had no `owner_module` (or supplied a scalar `writes` item), the linter could return `pass=true`. As File01 architecture governance is meant to reject cross-owner direct writes, silently dropping unrecognized write claims creates false confidence.

Two negative cases were added in `tests/future-foundation-tests.php` before the fix at **test-only commit** `0d991a1a154460f11cca919e32c120b59fe4639a`. GitHub Actions red run **43806519845** PHP 8.1 and PHP 8.3 both failed precisely:
- `F01-FUT-003: missing write owner was silently treated as a clean architecture.`
- `F01-FUT-003: scalar write declaration bypassed canonical write ownership checks.`

## Bounded correction

Every declared write now requires an array with an exactly canonical `owner_module` of form `file-00`…`file-26`. Missing, scalar, foreign/invalid identities produce **critical** `invalid_write_owner_declaration`. Valid foreign canonical owner references continue to produce the prior **high** `foreign_direct_write`. Valid same-owner structured writes remain allowed; missing entire `writes` field remains no claim, and source-intake requires `writes` to be an array. This does not change database schema or authorization and does not modify any foreign owner.
