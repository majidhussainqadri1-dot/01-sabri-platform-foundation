## Proven cause and deliberately failing source test

`SPF_Authorization::validate_claim()` accepted a `claim_version` meeting `SPF_Registry::valid_semver()` but then tested its lower bound with PHP `version_compare()`. PHP parses SemVer build metadata as precedence-related (for example `version_compare('1.0.0+build.2','1.0.0') === -1`), whereas Semantic Versioning explicitly ignores build metadata in precedence. Consequently a valid, equal-precedence File00 claim might be incorrectly rejected. This is a **false denial/compatibility defect**, not an unauthorized permission grant or observed live security bypass.

Added three source unit assertions: validate `1.0.0+build.2` syntax, permit its valid structured claim at stable `1.0.0` floor, still reject `1.0.0-alpha.1` prerelease below the stable floor. **Test-only exact commit:** `51d0fc0fd9cdf262c79ccbb146034287ade4ffee`. **GitHub Actions Run 43799813355**: PHP8.1 and PHP8.3 source jobs failed with exactly `F01-NFR-001: valid claim 1.0.0+build.2 incorrectly rejected below stable 1.0.0.` This is reproducible repository-level evidence only.
