# F01-FUT-003 — Shell owner summary mismatch audit and correction

**Date:** 2026-11-16. **Scope:** File 01-B source-only architecture lint in Draft PR #14. Relevant V12.3 rule: File 20 exclusively owns global application shell/navigation; File25 is the visual owner without duplicate shell ownership.

## Reproducible root cause

`SPF_Governance_Control_Plane::lint_architecture()` checked only caller-supplied `global_shell_owners` for shell ownership. If `global_shell_owners=['file-20']` was passed alongside a File21 or File25 module manifest declaring `global_shell_owner=true` or `application_shell_owner=true`, the linter previously returned `pass=true` when no canonical entities/routes overlapped. A summary was thus trusted over conflicting underlying declarations.

Two negative tests were added at exact test-only commit `3dbf83666554871d76aa5285d12667957baecc46`. GitHub Actions run `43803293684` failed source QA on PHP 8.1 and 8.3 exactly:
- `F01-FUT-003: embedded competing shell owner flag bypassed architecture linter.`
- `F01-FUT-003: embedded application shell owner flag bypassed architecture linter.`

## Bounded correction

Compute shell ownership from **both** the supplied summary and every module's own boolean `global_shell_owner`/`application_shell_owner` flags and canonical `global-shell`/`application-shell`/`global-navigation` entities. Deduplicate the aggregate and enforce `file-20` as the sole owner. Preserve the existing read-only source collector, all domain boundaries, API signatures, and schema. This is a validation fix, **not** an authorization to change File 20, File 21 or File 25.

**Acceptance limits:** Fresh exact final-head GitHub Actions, true owner manifests, independent File24 review, Hostinger deployed files/schema/migrations, staging integration and live verification remain separately required.
