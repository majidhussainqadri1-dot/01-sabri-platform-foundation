# File 01 — Sixth Fresh Ten-Round Review and Fix Cycle — 2026-08-08

This is a sixth independent adversarial review of the exact File 01 v2.0 Future Foundation corrective source after the fifth ten-round cycle. The governing basis remains the consolidated central plan plus the File 01 v2.0 Future Foundation plan. Each round was completed before its discovered defect(s) were corrected, then the affected scope was checked again. Staging/live/operational acceptance remain separate gates.

1. **Activation/cron rollback fidelity.** The activation snapshot stored the Future Foundation five-minute job, but rollback restoration mapped every non-outbox/non-privacy hook to hourly. `spf_future_foundation_tick` could therefore return with the wrong recurrence while System Check only verified that some schedule existed. Fixed by exact recurrence mapping and recurrence-aware health checks.
2. **Activation snapshot and compensation truth.** Snapshot persistence itself was not read-back verified, and option/capability/unschedule restoration could fail without being added to compensation failures. Fixed with snapshot read-back verification plus shadow cleanup on snapshot-persistence failure, option/capability restoration verification, unschedule verification and restored recurrence verification.
3. **Manifest identity truth.** Required owner name, slug and namespace prefix could be present before normalization but sanitize to empty values and still be accepted. Fixed with post-normalization non-empty identity validation.
4. **Authoritative dependency graph integrity.** Golden-Path scaffolding rejected self-dependency, but the canonical manifest registry itself still accepted a manifest whose required/optional dependency referenced its own module key. Fixed at the authoritative registry boundary.
5. **Bounded registry/governance completeness.** `canonical_entities` and `writes` could be silently truncated at 128, and a 251st policy could silently displace an existing policy after sorting. Invalid canonical-entity/write-operation declarations could also be normalized away. Fixed by explicit pre-mutation capacity errors and strict architecture-declaration validation; policy catalog overflow now fails without dropping prior policy truth.
6. **Contract lifecycle timestamp truth.** A non-empty invalid `deprecation_at` could pass through `strtotime(false)` and be stored as an epoch date instead of being rejected. Fixed by explicit parse validation before canonical UTC persistence.
7. **Runtime lock lease ownership.** Stale-lock takeover compared the existing lock age against the contender's requested TTL. A later caller with a shorter TTL could steal a still-valid longer lock. Fixed by persisting each lock's own TTL/expiry and using that lease for takeover; legacy lock payloads receive a conservative recovery window.
8. **File 00 structured-claim boundary.** The legacy boolean bridge was described as non-sensitive read/maintenance compatibility but could authorize mutating registry/governance actions whenever a structured claim was absent. Fixed so legacy booleans are accepted only for read-only `view`/`system_check`; mutations require structured actor/object/purpose-bound File 00 claims when File 00 is present.
9. **Privacy/destructive-operation fail-closed truth.** Missing `privacy_holds` storage returned “no hold”, and purge row/hold count query failures could be cast to zero. Fixed so a missing/query-failed hold registry blocks erasure, purge plans record inventory query failures, and destructive purge refuses to proceed when inventory truth cannot be verified.
10. **Event/telemetry/Golden-Path contract strictness.** Event schemas could silently truncate fields beyond 100; non-canonical fixture keys could alias a declared optional field after sanitization; telemetry `sampled` coerced arbitrary truthy values; Golden-Path dependencies used a different 100-item/silent-dedup law than the canonical 64-item/duplicate-reject registry and could declare the same module as required and optional. Fixed with explicit schema overflow/canonical-field errors, exact fixture field matching, literal boolean sampling, and Golden-Path dependency rules aligned with the canonical registry.
