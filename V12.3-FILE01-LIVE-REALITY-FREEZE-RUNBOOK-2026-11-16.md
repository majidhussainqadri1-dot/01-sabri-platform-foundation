## Sequential evidence collection (read-only, non-destructive)

1. **Access and time provenance:** record target `LIVE` or `STAGING` explicitly, full host/URL, UTC time, operator access channel and access authorization. Collect no passwords, tokens or private SSH keys in reports. Retain minimal redacted machine logs.
2. **Runtime freeze:** record WordPress core, PHP, MySQL, active theme, active plugin slugs/versions, active File01/00/02/20/21/24/25/26 source package versions and configuration-dependent provider activation; store a bounded plugin inventory. Distinguish plugin header versions from actual deployed code checksums.
3. **Deployed artifact freeze:** hash the exact File01 deployed plugin files and compare with the actual release-package source manifest. A single main-file hash does not prove whole-package parity. Record checksums independently from GitHub, staging and production.
4. **Database/schema freeze:** read only the listed safe File01 version options, `SHOW COLUMNS`/`SHOW INDEX` and table-engine/row-count metadata on the true `$wpdb->prefix . 'spf_'` tables, plus bounded nonprivate migration checkpoint fields. Do **not** export patient/member records, private options, email, notes, tokens or other sensitive rows.
5. **Incident/log freeze:** collect runtime errors, rewrite/cron/queue indicators, relevant consent- and release-state metadata and redacted log time windows; public error messages/screenshots are **symptoms** only and cannot prove a code defect.
6. **Deployment parity:** exact deployed build/checksum ↔ exact source SHA ↔ actual DB/schema/migrations ↔ companion dependencies. If any mismatch appears, stop routine debugging and perform a Deployment-Parity Audit. Any source-based code diagnosis without deployed parity remains **provisional**.
7. **Staging acceptance:** validate authorized backup, independent restore, fresh/upgrade/rollback, role and ownership matrix, cross-file contracts, keyboard/RTL/browser, p75/p95 and operational alerts. Independent File24 validation is required. No live migration, uninstall, purge, repair, self-heal or disabled security controls during evidence collection.
8. **Controlled release and live re-test (not done):** after explicit Founder go/no-go, exact artifact package, rollback plan and monitoring: deploy only authorized scope, run live route/permission/migration smoke and checksum parity. Without those receipts mark **Not Resolved**, even if GitHub CI is green.
